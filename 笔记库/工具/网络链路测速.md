# 网络链路测速

> 测本地到远程主机的真实网络质量：延迟、单流吞吐、多流吞吐、服务器出网带宽。
>
> 零依赖——只用 `ping` / `ssh` / `scp` / `curl`，远程主机什么都不用装。脚本：`nettest.py`

## 解决什么问题

拿到一台新服务器，需要回答的其实是这几个问题：

- SSH 交互跟不跟手？（延迟）
- 传代码/数据要多久？（吞吐）
- **慢是慢在哪一侧**？是我这边的链路差，还是服务器带宽小？

最后一个最关键，因为结论完全不同：链路差就该让服务器自己去拉代码，服务器带宽小才需要升级配置。常规测速工具（speedtest 之类）只测「本机到某公共节点」，回答不了这个问题。

## 为什么不用 iperf3

iperf3 是测带宽的标准工具，更准，但这里没选它：

| 方案 | 优点 | 代价 |
| :--- | :--- | :--- |
| iperf3 | 精确，不受加密影响，支持 UDP 抖动测试 | 两端都要装，服务器要开端口 + 配云安全组，换台机器就得重做一遍 |
| SSH/scp | 零部署，有 SSH 就能测 | 走加密通道，实测值比裸带宽略低 |

选 SSH 的真正理由不是"图省事"：**日常传代码、部署、同步文件本来就走 SSH**。测 SSH 通道的实际吞吐，比 iperf3 的理论带宽更贴近真实体感。iperf3 告诉你"这条链路能跑 100Mbps"，而 scp 告诉你"你 push 代码时就是这么慢"。

## 测量的五个维度

| 维度 | 方法 | 能回答什么 |
| :--- | :--- | :--- |
| 延迟 / 抖动 / 丢包 | `ping -c 10` | SSH 交互是否跟手 |
| 单流上传 | scp 推一个文件 | 部署推送的真实速度 |
| 单流下载 | scp 拉回来 | 是否上下行不对称 |
| 多流并行 | 切片后 N 路并发 scp | 瓶颈是链路本身还是单流窗口 |
| 服务器出网 | ssh 到服务器上 curl 公共测速文件 | **瓶颈在哪一侧** |

## 四个关键方法

### 单流 vs 多流：区分两种"慢"

同样是 10Mbps，成因可能完全不同：

- **链路真的只有 10Mbps** → 多流并行也还是 10Mbps
- **单流受高延迟压制** → 多流并行能显著突破

原理是 TCP 的带宽时延积（BDP）：单条 TCP 连接的吞吐上限约等于 `窗口大小 / RTT`。RTT 300ms 时，即使链路很宽，单流也很难跑满——但开 4 条流就能接近 4 倍。

所以多流增益是个诊断信号：

- 增益 ≥ 1.5x → 值得用 rsync 多进程或分片并发传大文件
- 增益 ≈ 1x → 链路本身就这个量级，调并发没意义

### 服务器出网：定位瓶颈在哪一侧

这是整套方法里最有价值的一步。在服务器上 curl 一个公共大文件，测它自己的出网能力，再和「你到服务器」的速度对比：

```text
你 → 服务器      8 Mbps
服务器 → 互联网  69 Mbps
```

结论立刻清晰：**瓶颈在你这一侧的链路，服务器带宽完全没吃满**。这种情况下升级服务器配置毫无意义，正确做法是让服务器自己去 GitHub 拉代码（它到 GitHub 只要 74ms），而不是从本地 scp 推上去。

反过来如果两个数字接近，才说明是服务器带宽到顶了。

### 用不可压缩数据

测试文件必须用 `os.urandom()` 生成，且 scp 显式关掉压缩（`-o Compression=no`）。

否则传一个全零文件，压缩后几乎不占带宽，测出来的数字是假的。

### 自适应样本 + 一个"有偏但正确"的设计

固定文件大小在两个极端都不合适：链路慢时等太久，链路快时样本太小测不准。所以先传 5MB 探速，再据此选一个耗时约 15 秒的样本。

**但探测值本身是不准的**——小文件里 SSH 握手和 TCP 慢启动占比大，高延迟链路上会明显低估。实测中探测报 2.7 Mbps，真实是 6.6 Mbps。

这个偏差**没有去修正**，因为它是自我修正的：

- 链路越慢 → 低估越多 → 选的样本越小 → 你等得越短
- 链路快时 → 5MB 传得快、固定开销占比小 → 估得准 → 选合适的大样本

偏差方向恰好帮忙。真正要做的是**不把探测值当测量结果展示**——早期版本把它打印出来，结果和下面的实测数字矛盾，徒增困惑。现在只显示选定的样本大小。

## 脚本解析

### 头部与常量

```python
#!/usr/bin/env python3
"""测试本地到远程主机的网络质量。

零依赖：只用 ping / ssh / scp / curl，远程主机无需安装任何东西。

用法:
    ./nettest.py                          # 测默认主机
    ./nettest.py ubuntu@1.2.3.4           # 测指定主机
    ./nettest.py ubuntu@1.2.3.4 --size 100
"""

import argparse
import os
import re
import shutil
import subprocess
import sys
import tempfile
import time
from concurrent.futures import ThreadPoolExecutor

DEFAULT_HOST = "ubuntu@43.155.173.41"
PARALLEL_STREAMS = 4
PROBE_MB = 5
TARGET_SECONDS = 15
SIZE_RANGE_MB = (20, 200)

# 服务器出网测速源，按顺序尝试直到拿到完整下载
EGRESS_SOURCES = [
    ("OVH", "https://proof.ovh.net/files/100Mb.dat", 100 * 1024 * 1024 // 8),
    ("Hetzner", "https://ash-speed.hetzner.com/100MB.bin", 100 * 1024 * 1024),
]

SSH_OPTS = ["-o", "BatchMode=yes", "-o", "ConnectTimeout=10"]
SCP_OPTS = SSH_OPTS + ["-o", "Compression=no"]
```

`SIZE_RANGE_MB` 给自适应加上下限兜底，避免极端链路上选出荒唐的样本大小。

`BatchMode=yes` 让 SSH 在需要交互（密码、确认指纹）时直接失败而不是挂起——脚本不能卡在等输入。

### 基础工具

```python
def run(cmd, timeout=180):
    """执行命令，返回 (returncode, stdout+stderr)。"""
    try:
        p = subprocess.run(
            cmd, capture_output=True, text=True, timeout=timeout, check=False
        )
        return p.returncode, p.stdout + p.stderr
    except subprocess.TimeoutExpired:
        return 124, "timeout"
    except FileNotFoundError:
        return 127, "command not found"


def mbps(size_bytes, seconds):
    if seconds <= 0:
        return 0.0
    return size_bytes * 8 / seconds / 1_000_000


def fmt_rate(rate):
    return "%.1f Mbps (%.2f MB/s)" % (rate, rate / 8)


def host_only(host):
    return host.split("@", 1)[-1]


def check_ssh(host):
    code, out = run(["ssh"] + SSH_OPTS + [host, "true"], timeout=20)
    if code != 0:
        sys.exit("无法连接 %s\n%s" % (host, out.strip()))
```

`fmt_rate` 同时给出 Mbps 和 MB/s：前者是运营商口径，后者是你看进度条时的直觉单位，省得心算除以 8。

### 延迟测量

```python
def test_latency(host):
    """ping 测延迟与丢包，兼容 macOS 与 Linux 的输出格式。"""
    code, out = run(["ping", "-c", "10", host_only(host)], timeout=60)
    if code != 0:
        return None

    loss = re.search(r"([\d.]+)%\s*packet loss", out)
    stats = re.search(r"=\s*([\d.]+)/([\d.]+)/([\d.]+)(?:/([\d.]+))?\s*ms", out)
    if not stats:
        return None

    return {
        "min": float(stats.group(1)),
        "avg": float(stats.group(2)),
        "max": float(stats.group(3)),
        "jitter": float(stats.group(4)) if stats.group(4) else None,
        "loss": float(loss.group(1)) if loss else None,
    }
```

正则里第四组用 `(?:...)?` 包成可选——macOS 的 ping 输出 `min/avg/max/stddev` 四个值，Linux 是 `min/avg/max/mdev`，但某些环境只有三个。写成可选就不用分平台处理。

`ping` 失败返回 `None` 而非报错退出：ICMP 常被防火墙拦截，但这不影响其余测量，不该让整个脚本挂掉。

### 传输原语

```python
def make_file(path, size_mb):
    """生成不可压缩的测试文件，避免压缩掩盖真实吞吐。"""
    with open(path, "wb") as f:
        f.write(os.urandom(size_mb * 1024 * 1024))


def upload(local, host, remote_dir="/tmp"):
    start = time.monotonic()
    code, out = run(["scp"] + SCP_OPTS + [local, "%s:%s/" % (host, remote_dir)])
    if code != 0:
        raise RuntimeError("上传失败: %s" % out.strip())
    return time.monotonic() - start


def download(remote_path, host, local):
    start = time.monotonic()
    code, out = run(["scp"] + SCP_OPTS + ["%s:%s" % (host, remote_path), local])
    if code != 0:
        raise RuntimeError("下载失败: %s" % out.strip())
    return time.monotonic() - start
```

计时用 `time.monotonic()` 而非 `time.time()`——后者受系统时钟调整（NTP 校时）影响，测量长耗时操作可能出现负数或跳变。

### 自适应样本大小

```python
def pick_size(host, workdir, explicit_mb):
    """先用小文件探速，据此选出耗时接近 TARGET_SECONDS 的测试大小。

    探测值只用来定量级，不作为测量结果：小文件里 SSH 握手和 TCP 慢启动
    占比大，高延迟链路上会明显低估。这个偏差是自我修正的——越慢的链路
    低估越多，选的文件越小，等待时间越短。
    """
    if explicit_mb:
        return explicit_mb, None

    probe = os.path.join(workdir, "probe.bin")
    make_file(probe, PROBE_MB)
    try:
        seconds = upload(probe, host)
    finally:
        os.remove(probe)
        run(["ssh"] + SSH_OPTS + [host, "rm -f /tmp/probe.bin"], timeout=30)

    rate = mbps(PROBE_MB * 1024 * 1024, seconds)
    size = int(rate / 8 * TARGET_SECONDS)
    size = max(SIZE_RANGE_MB[0], min(SIZE_RANGE_MB[1], size))
    return size, rate
```

`finally` 里同时清理本地和远端的探测文件——测速工具不该在别人机器上留垃圾。

### 多流并行

```python
def test_parallel(local, host, streams, size_mb):
    """把文件切成 N 份并发上传，看多流能否突破单流上限。"""
    parts = []
    chunk = size_mb * 1024 * 1024 // streams
    with open(local, "rb") as f:
        for i in range(streams):
            part = "%s.p%d" % (local, i)
            with open(part, "wb") as out:
                out.write(f.read(chunk))
            parts.append(part)

    try:
        start = time.monotonic()
        with ThreadPoolExecutor(max_workers=streams) as pool:
            list(pool.map(lambda p: upload(p, host), parts))
        elapsed = time.monotonic() - start
    finally:
        for p in parts:
            os.remove(p)
        names = " ".join("/tmp/%s" % os.path.basename(p) for p in parts)
        run(["ssh"] + SSH_OPTS + [host, "rm -f %s" % names], timeout=30)

    return mbps(chunk * streams, elapsed)
```

用线程池而非多进程：这里每个任务都是等待外部 `scp` 进程，属于 IO 密集，GIL 不构成瓶颈。

计时覆盖的是**整体墙钟时间**，不是各流耗时之和——并行的意义正在于此。

### 服务器出网

```python
def test_egress(host):
    """在服务器上下载公共测速文件，判断服务器自身出网带宽。"""
    for name, url, expect in EGRESS_SOURCES:
        cmd = (
            'curl -sL -o /dev/null --max-time 60 '
            '-w "%%{size_download} %%{time_total}" "%s"' % url
        )
        code, out = run(["ssh"] + SSH_OPTS + [host, cmd], timeout=90)
        if code != 0:
            continue
        try:
            size, seconds = out.split()[-2:]
            size, seconds = int(size), float(seconds)
        except ValueError:
            continue
        # 源失效时会返回错误页而非文件，用期望大小过滤掉
        if size >= expect * 0.9:
            return name, mbps(size, seconds)
    return None, None
```

**必须校验下载大小**。实测踩过：Cloudflare 的测速端点返回 403（只有 1 字节），CacheFly 的文件失效后返回 25 字节的错误页——如果不校验，会算出一个荒谬的"速率"并当成结果。所以按期望大小的 90% 过滤，不达标就换下一个源。

`-o /dev/null` 让文件不落盘，避免磁盘 IO 干扰测量，也不占服务器空间。

### 主流程

```python
def main():
    ap = argparse.ArgumentParser(
        description="测试本地到远程主机的网络质量",
        formatter_class=argparse.RawDescriptionHelpFormatter,
    )
    ap.add_argument("host", nargs="?", default=DEFAULT_HOST,
                    help="目标主机，默认 %s" % DEFAULT_HOST)
    ap.add_argument("--size", type=int, metavar="MB",
                    help="测试文件大小，默认按实测速率自适应")
    args = ap.parse_args()

    host = args.host
    for tool in ("ssh", "scp", "ping"):
        if not shutil.which(tool):
            sys.exit("缺少命令: %s" % tool)

    print("目标: %s\n" % host)
    check_ssh(host)

    lat = test_latency(host)
    if lat:
        line = "延迟        %.0f ms  (%.0f~%.0f" % (lat["avg"], lat["min"], lat["max"])
        if lat["jitter"] is not None:
            line += ", 抖动 %.0f" % lat["jitter"]
        line += " ms)"
        print(line)
        if lat["loss"] is not None:
            print("丢包        %.0f%%" % lat["loss"])
    else:
        print("延迟        测量失败（ICMP 可能被拦截）")

    workdir = tempfile.mkdtemp(prefix="nettest-")
    local = os.path.join(workdir, "payload.bin")
    remote = "/tmp/payload.bin"

    try:
        size_mb, probe_rate = pick_size(host, workdir, args.size)
        if probe_rate is not None:
            print("测试样本    %d MB（按探测速率自适应）" % size_mb)
        print()

        make_file(local, size_mb)

        up = mbps(size_mb * 1024 * 1024, upload(local, host))
        print("单流上传    %s" % fmt_rate(up))

        os.remove(local)
        down = mbps(size_mb * 1024 * 1024, download(remote, host, local))
        print("单流下载    %s" % fmt_rate(down))

        par = test_parallel(local, host, PARALLEL_STREAMS, size_mb)
        gain = par / up if up else 0
        print("%d 流并行    %s  (单流的 %.1fx)" % (PARALLEL_STREAMS, fmt_rate(par), gain))

        name, egress = test_egress(host)
        if egress:
            print("服务器出网  %s  [%s]" % (fmt_rate(egress), name))
        else:
            print("服务器出网  测量失败（测速源不可达）")

        print()
        summarize(lat, up, par, gain, egress)
    finally:
        shutil.rmtree(workdir, ignore_errors=True)
        run(["ssh"] + SSH_OPTS + [host, "rm -f %s" % remote], timeout=30)
```

下载测试前先 `os.remove(local)`，确保拉回来的是真实传输而非本地已有文件。

最外层 `finally` 保证本地临时目录和远端文件一定被清理，即使中途异常。

### 把数字翻译成判断

```python
def summarize(lat, up, par, gain, egress):
    """把测量值翻译成对使用方式的判断。"""
    notes = []

    if lat:
        if lat["avg"] < 50:
            notes.append("延迟低，交互式操作跟手。")
        elif lat["avg"] < 150:
            notes.append("延迟中等，SSH 交互可接受。")
        else:
            notes.append("延迟高，SSH 交互和 vim 编辑会有明显滞后，不适合当日常开发机。")

    if egress and up and egress > up * 2:
        notes.append(
            "瓶颈在你到服务器的链路，不是服务器带宽"
            "（服务器出网 %.0f Mbps，你只能跑到 %.0f Mbps）。" % (egress, up)
        )
        notes.append("部署代码建议走 git 让服务器自己拉，别从本地 scp 推。")

    if gain >= 1.5:
        notes.append("多流并行能提速 %.1f 倍，传大文件时用 rsync 多进程或分片并发。" % gain)
    elif par:
        notes.append("多流并行提升有限，链路本身就这个量级，调并发意义不大。")

    if up:
        minutes = 1024 / (up / 8) / 60
        notes.append("按当前速度，传 1GB 约需 %.0f 分钟。" % minutes)

    if notes:
        print("结论")
        for n in notes:
            print("  - %s" % n)


if __name__ == "__main__":
    try:
        main()
    except KeyboardInterrupt:
        sys.exit("\n已中断")
    except RuntimeError as e:
        sys.exit("错误: %s" % e)
```

这一段是整个脚本的落点：**裸数字没有意义，能指导决策才有**。

`egress > up * 2` 这个判据触发时，直接给出"走 git 别 scp"的行动建议——这正是测量的目的。「传 1GB 需要几分钟」也比「8 Mbps」直观得多。

## 局限

**单次结果波动大，别拿一次测量下结论。** 同一条链路连测两次，单流下载曾出现 6.2 → 11.3 Mbps 的差异，多流增益的判定也随之从"值得用"翻到"意义不大"。跨境链路本身抖动就大（抖动从 8ms 到 23ms）。

要对比两个环境的优劣，同一环境至少跑 2~3 次看区间。这不是脚本的缺陷，是链路的真实状态。

其余已知限制：

- 走 SSH 加密通道，实测值比裸带宽略低（但更贴近实际使用体感）
- 不测 UDP 抖动和丢包分布，有这类需求还是得用 iperf3
- ICMP 被拦截时延迟测不出来，但不影响其余项

## 附：判断端口是否放行

不属于本脚本，但同一场景常用。**在目标端口没有服务监听时**，也能区分"防火墙拦截"和"端口开放"：

```bash
curl -s -o /dev/null --connect-timeout 6 http://<IP>:<PORT>/; echo $?
```

- **返回 7（refused）** → 包到达了主机，只是没有服务在监听，说明**防火墙放行**
- **返回 28（timeout）** → 包被静默丢弃，说明**防火墙拦截**

排查云服务器安全组时特别有用——不用先起个服务就能验证端口是否开放。
