# 接入新机器

> 把一台新设备加进 tailnet 的完整流程：服务端命令 + 各平台客户端操作。
> 控制面地址统一为 `https://hs.yiko.site`。

## 先选接入方式

两种方式，区别在于**谁先动**：

|           x     | 预授权密钥（authkey）               | 交互注册                  |
| -------------- | ----------------------------------- | ------------------------- |
| 顺序           | 服务端先发 key → 客户端一条命令接入 | 客户端先申请 → 服务端批准 |
| 客户端额外操作 | 无                                  | 要把注册 ID 抄到服务端    |
| 适合           | Linux、批量部署、无人值守           | 手边就能操作服务端的场合  |


**能填 authkey 就填 authkey**（Linux、Windows、Android 都支持），省掉一次来回。iOS / iPadOS
和 macOS GUI 只能走交互注册。

## 服务端操作

登录 VPS——tailnet 内 `ssh ubuntu@100.64.0.1`，或公网 `ssh ubuntu@43.155.173.41`。
以下命令都要 `sudo`。

### 查用户和 ID

```bash
sudo headscale users list
```

```text
ID | Username | Created
1  | zy       | 2026-08-18 02:50:01
```

下面两条命令都要用户，但**一个要 ID、一个要用户名**，先记住这个不一致。

### 方式一：生成预授权密钥

```bash
sudo headscale preauthkeys create -u 1 --expiration 24h
```

> **坑**：`-u` 在这里必须是**用户 ID（数字）**，填用户名会报错。

| 选项 | 作用 |
| --- | --- |
| `-e` / `--expiration` | 有效期，如 `30m` / `24h`，默认 `1h` |
| `--reusable` | 可重复使用，适合一次装多台 |
| `--ephemeral` | 临时节点，断线后自动从列表移除，适合容器 / 临时机器 |
| `--tags` | 自动打标签 |

**默认是一次性的**，用完即失效——给单台机器用这样最安全。

查看已有的 key：

```bash
sudo headscale preauthkeys list -u 1
```

### 方式二：批准交互注册

客户端填完控制面地址后会显示一串 `hskey-authreq-xxxxx`，在服务端执行：

```bash
sudo headscale auth register --auth-id hskey-authreq-xxxxx --user zy
```

> **坑**：这里的 `--user` 要**用户名（字符串）**，跟 `preauthkeys create` 正好相反。

### 确认结果

```bash
sudo headscale nodes list
```

新设备会拿到 `100.64.0.x` 和一个 `fd7a:115c:a1e0::x`。

### 改名

```bash
sudo headscale nodes rename -i <节点ID> <新名字>
```

主机名含中文或空格会被规范化，例如 `zy的MacBook Air` → `zymacbook-air`。**MagicDNS 用的是
规范化后的名字**，`ssh` 时要用它。

### 批准路由（Exit Node / 子网）

客户端通告的路由**默认不生效**，必须服务端批准：

```bash
sudo headscale nodes list-routes                              # 看谁通告了什么
sudo headscale nodes approve-routes -i <节点ID> -r 0.0.0.0/0,::/0
```

- **Exit Node 必须同时批 `0.0.0.0/0` 和 `::/0`**，只批 IPv4 的话客户端永远不认它是出口节点
- 子网路由写实际网段，如 `-r 192.168.1.0/24`
- `-r ""` 清空所有已批准路由

### 移除设备

```bash
sudo headscale nodes expire -i <节点ID>    # 登出，设备可重新登录
sudo headscale nodes delete -i <节点ID>    # 彻底删除
```

## 客户端

### Linux

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --login-server=https://hs.yiko.site --authkey=<preauthkey>
```

作为 Exit Node 或子网路由器接入时加上对应参数，之后回服务端批准路由：

```bash
sudo tailscale up --login-server=https://hs.yiko.site --authkey=<key> \
  --advertise-exit-node                      # 出口节点
sudo tailscale up --login-server=https://hs.yiko.site --authkey=<key> \
  --advertise-routes=192.168.1.0/24          # 子网路由
```

Exit Node 还需要开转发，否则流量会被丢弃：

```bash
echo 'net.ipv4.ip_forward = 1'          | sudo tee /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
```

### macOS

**standalone 版**（从 tailscale.com 下载，推荐）：

- App 里 `Add Account…` 旁的下拉箭头 → **Add Account Using Alternate Server** → 填控制面地址
- 或菜单栏按住 `Option` 点图标 → Debug → **Custom Login Server**

**App Store 版**入口相同，但沙箱限制更多。

CLI 在 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`，不在 `PATH` 里，建议配别名。

### Windows

装官方客户端后，用 CLI 最省事（`tailscale.exe` 在 `C:\Program Files\Tailscale\`）：

```powershell
tailscale login --login-server https://hs.yiko.site
```

然后按浏览器提示完成。要让 Tailscale 在用户注销后继续运行：托盘图标 → `Preferences` →
勾选 **Run unattended**。

注册反复失败时的清理步骤：停止 Tailscale 服务 → 删除
`C:\Users\<用户名>\AppData\Local\Tailscale` → 在服务端 `nodes delete` 掉该节点 → 重新登录。

### iOS / iPadOS

需要 Tailscale ≥ 1.38.1，两个入口任选：

- App 内：账户图标 → Log in → 右上角选项 → **Use custom coordination server**
- 系统设置 → Tailscale → **ALTERNATE COORDINATION SERVER URL**

**没有 CLI**，Exit Node 只能从 GUI 选。若接入初期列不出可用出口节点，是 online 状态位收敛
延迟，等一会即可，详见[主笔记](../Headscale%20自建网络部署.md)。

### Android

- 设置菜单（右上角）→ **Accounts** → 右上角三点菜单 → **Use an alternate server** → 填地址
- 同一菜单里的 **Use an auth key** 可以直接填预授权密钥，跳过交互注册

Google Play 和 F-Droid 都有。

### 平台指引页

headscale 自带两个页面，浏览器打开即可，内容随版本更新：

```text
https://hs.yiko.site/apple
https://hs.yiko.site/windows
```

## 接入后检查

在**新设备**上：

```bash
tailscale status          # 应看到全部节点，理想状态是 direct 而非 relay
tailscale netcheck        # 看 NAT 类型和 DERP 延迟
```

从**已有设备**验证连通性：

```bash
tailscale ping <新设备名>              # tailnet 层，绕过应用层防火墙
ping <新设备IP>
```

> 注意 tailnet 用的是 `100.64.0.0/10` 段。写成 `10.64.0.x` 会落进 `10.0.0.0/8`，
> 表现为**连接超时**（无主机应答）而不是拒绝——踩过一次。

**SSH 免密是按机器配的**，与 tailnet 无关。新机器要免密登录 VPS，得把它的公钥装上；在一台
已免密的机器上执行：

```bash
ssh ubuntu@100.64.0.1 'cat >> ~/.ssh/authorized_keys' < 新机器的_id_ed25519.pub
```

Lighthouse 的 `ubuntu` 用户通常没设密码，`ssh-copy-id` 走不通。

## 常见问题

**填了地址却没反应** — 先确认控制面本身健康：

```bash
curl https://hs.yiko.site/health      # 期望 {"status":"pass"}
```

**节点在线但连不通** — 用 `tailscale ping` 判断是 tailnet 层不通还是对端服务/防火墙问题。
`tailscale ping` 通而 `nc -vz <ip> 22` 不通，就是对端没开服务或被本机防火墙拦了。

**通告了路由却不生效** — 服务端没批准。`nodes list-routes` 里 Available 和 Approved 是两列，
只出现在 Available 里等于没批。

**设备名对不上** — 用 `nodes list` 里的 Name 列（规范化名），不是 Hostname 列。
