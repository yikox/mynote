> 状态：独立审核已完成，方案已按审核意见修订，待确认后实施
> 规划范围：将 Plexus 当前被动式 AI 对话改造成可主动运行的 AI 助手
> 验收方式：自动化测试 + Computer Use 实际操作已安装的 Plexus 应用

## 1. 目标状态

### 1.1 最终产物

将现有 AI 页面改造成一个 AI 助手面板。系统只有一个长期存在的主助手，不在第一阶段拆分多个长期 Agent。

主助手可以：

- 按计划自动执行任务；
- 主动检查整个笔记库；
- 定时检索指定主题；
- 发现问题后主动发起对话；
- 保留用户偏好、任务、历史发现、处理决定和对话，并按任务相关性加载记忆；
- 提出笔记修改建议，但未经确认不修改笔记。

### 1.2 核心使用场景

#### 主动检查笔记

助手发现重复笔记、相关但尚未建立联系的笔记、可能需要拆分的长笔记，以及内容疑似过时或冲突的笔记。

发现问题后，以 AI 对话消息主动告知用户，说明涉及笔记、判断依据和建议处理方式。

#### 定时检索主题

用户设置主题和执行时间，助手定时检索外部资料，与已有笔记比较，整理新增或变化的信息、来源及建议，并在助手面板中发起对话。

#### 用户主动交代任务

保留当前主动对话能力。用户可以临时要求助手检查笔记、整理知识、研究主题或执行其他任务；任务结果进入助手的运行记录和记忆体系。

#### 确认后执行修改

助手先发现问题并与用户沟通，用户确认“处理这个问题”的意图后生成结构化修改方案；执行前重新校验文件并展示实际 diff，用户在 diff 界面做最终允许后才写入、移动、拆分或删除。用户拒绝、取消或前置条件失效时，笔记保持不变。

### 1.3 已确认的授权边界

- 助手可以读取整个笔记库；
- 助手可以读取完整历史和长期记忆；
- 助手可以执行已经配置的定时任务和主动巡检；
- 不增加每种能力单独开启的授权开关；
- 自动巡检和定时研究默认只读；
- 实际修改、移动、拆分和删除笔记仍必须经过用户确认。

### 1.4 明确不包含

- Plexus 关闭时运行；
- 多个独立的长期助手；
- 未经确认的笔记写入、删除、移动或发布；
- 独立的系统通知中心；
- 复杂的多 Agent 协作。

## 2. 验收与验证

### 2.1 验收原则

- 自动化测试验证数据、状态、调度、运行时和工具安全边界。
- 手动验收必须使用 Computer Use 操作已安装的 `/Applications/Plexus.app`。
- 手动验收不以 DOM 断言或单元测试代替，必须通过真实界面完成操作并记录结果。
- 手动验收应使用真实工作区中的测试笔记和可控任务数据，必要时保留截图或操作记录。
- 用户是最终验收人。

### 2.3 关键验收场景

#### 场景 A：发现重复笔记

```text
助手定期检查笔记
    ↓
发现 A、B 内容高度重复
    ↓
主动发起对话并说明依据
    ↓
用户要求给出合并方案
    ↓
助手生成合并建议和 diff
    ↓
用户确认后才修改
```

#### 场景 B：定时研究主题

```text
用户设置“每周检索 AI Agent”
    ↓
助手按计划执行
    ↓
对比上次结果和已有笔记
    ↓
发现新的重要信息
    ↓
在助手面板主动发起对话
    ↓
用户决定是否整理进笔记
```

#### 场景 C：助手记忆用户偏好

```text
用户确认“研究结果默认整理成独立笔记”
    ↓
助手记录该决定
    ↓
下一次研究任务自动采用相同方式
    ↓
用户无需重复说明
```

#### 场景 D：切换工作区时取消旧任务

```text
工作区 A 有正在运行的巡检
    ↓
用户切换到工作区 B
    ↓
调度器停止接收 A 的新任务，取消并等待在途运行
    ↓
A 的旧请求、工具调用和确认全部失效
    ↓
助手面板只显示 B 的任务、发现和主对话
```

#### 场景 E：发现后的安全修改

```text
助手发现问题并与用户讨论
    ↓
用户确认要处理该问题
    ↓
助手生成结构化 MutationPlan
    ↓
重新读取并校验路径、工作区代际和内容 hash
    ↓
向用户展示准确 diff，用户在此处做最终允许/拒绝
    ↓
允许后执行；任何前置条件变化都停止并要求重新确认
```

## 3. 当前现状与约束

### 3.1 已有能力

- Agent 已经是 Markdown 配置文件。
- `runAgent` 已经支持多轮流式对话、上下文压缩和工具调用。
- 工具已覆盖笔记读写、搜索、Web 搜索和 Git 检查。
- 写工具已有用户确认弹窗和 diff 回执。
- 会话持久化在 `.plexus/agent/sessions/`。
- AI 页面已有运行状态、模型选择、工具调用状态和上下文统计。
- `fs://changed` 已提供笔记文件变化事件。
- `.plexus/agent/` 已有插件私有数据目录和通用 watcher 事件。
- `runAgent` 和 `AgentRuntime` 仍以 `sessionId` 为核心，包含会话写入、自动标题、Tab 状态和全局确认桥，不能直接作为后台运行入口。
- 工作区路径由全局状态和 Rust `AppState.workspace` 提供，笔记工具没有携带 workspace 身份或代际校验。
- 当前工具注册只有 `write: boolean`，没有只读、联网、副作用等能力声明；后台安全不能只依赖一个布尔开关。
- 当前 `ai_chat` 没有可查询的后端请求取消句柄，前端 `AbortSignal` 不能保证在途网络请求真正停止。
- 当前快照按 `sessionId` 保存在内存中，不能直接作为跨重启的助手长期记忆。

### 3.2 当前缺口

- 没有定时任务模型和任务调度器。
- 没有助手主动发起消息的机制。
- 没有任务、运行、发现和长期记忆的独立存储。
- 没有笔记巡检和重复检测流程。
- 当前 AI 页面以普通会话和会话侧栏为中心，不是助手面板。
- `AgentRuntime` 以 `sessionId` 为核心，尚无后台任务运行适配层。
- 当前确认弹窗是单个全局请求，后台任务不能直接阻塞等待确认。

### 3.3 约束

- 只能在应用运行期间调度，暂不设计应用关闭后的执行。
- 自动任务必须默认使用只读工具。
- 后台任务不能弹出一个会长期阻塞的确认请求；应先生成发现或建议，用户回到助手面板确认。
- 任务必须绑定工作区，工作区切换时停止旧工作区任务并重新加载。
- 任务运行必须避免与用户手动对话并发争抢同一助手状态。
- 主助手运行必须有单一调度 owner 和明确的优先级：用户主动任务优先于定时任务；同一主助手同一时间最多一个主动运行。
- 全库扫描不能每次无条件读取并发送全部笔记，应先做候选筛选，再交给 AI 判断。
- 记忆可以完整保存，但不能每次把全部记忆注入模型上下文，应使用相关性选择和压缩。
- 每个工作区拥有持久 `workspaceId`；每次打开或切换工作区递增 `workspaceGeneration`。运行、确认、发现和投影必须绑定二者。
- 所有后台任务必须使用显式只读工具白名单，并同时过滤给模型的工具 Schema；未知工具和新增工具默认拒绝。
- 应用关闭期间不执行任务，也不自动补跑关闭期间错过的周期。
- 前台写入必须使用带内容 hash 和工作区代际的 MutationPlan；前置条件失效时停止并重新确认。

## 4. 候选方案与决策

### 4.1 方案 A：扩展现有 Session

将助手变成一个特殊 Session，所有定时任务都追加到该会话。

优点：改动少，复用现有会话、上下文和 UI。

缺点：自动任务、人工对话、发现、记忆和任务记录混在一起；后台任务容易污染对话上下文，并产生并发冲突。

### 4.2 方案 B：新增 Assistant 域，抽取通用运行内核

新增任务、运行记录、发现、记忆和调度器；复用现有模型调用、Context、工具定义和结果协议，但先把 `runAgent` 中与 Session、Tab、全局确认和 UI 状态绑定的部分抽成通用运行内核。

优点：助手状态和普通会话边界清晰；可以逐步增加主动能力；保留现有 AI 能力和安全门。

缺点：需要新增 Assistant Runtime、持久化结构、面板和调度器，并先完成聊天运行与后台运行的适配层拆分。

### 4.3 方案 C：Rust 后台统一调度

由 Rust 负责调度、存储和 AI 运行，前端只展示状态。

优点：未来更容易支持应用关闭后运行。

缺点：当前需求不需要；会重复实现前端已有 Agent 编排；增加跨端状态、事件和调试复杂度。

### 4.4 最终选择

选择方案 B：新增 Assistant 域，抽取通用运行内核，复用现有 Agent Loop 中的模型流、Context、Tools 和结果协议。

主助手使用绑定的 Agent Definition 作为模型、提示词、上下文和工具策略来源；默认沿用当前选中的 Agent，但主助手第一次创建后保存 `agentId`，不因普通会话切换而漂移。每次任务运行都冻结 Agent、Provider/Model、工具注册表和安全策略快照，运行期间修改配置只影响下一次任务。

主助手保留每个工作区唯一的一条长期对话。普通 AI Session 仍作为历史入口存在，但不再作为主助手身份或后台任务容器。自动任务不把完整工具过程直接塞进主对话，而是保存为独立运行记录，并将重要发现以带来源、`runId`、`findingId` 和幂等 `projectionId` 的精炼助手消息投影到主对话中。

## 5. 目标数据模型

### 5.1 AssistantTask

表示可重复执行的任务，包含：

- id、工作区身份、名称、任务描述和任务类型（巡检、研究、用户任务）；
- 结构化输入（主题、查询、候选范围和来源策略）；
- 触发方式、时区、周期、`nextRunAt` 和 `scheduleVersion`；
- 是否启用；
- 上次运行时间、上次结果引用和当前状态；
- 任务绑定的 Agent、模型、工具策略快照引用；
- `revision` 和幂等配置，用于防止手动触发与定时触发重复执行。

### 5.2 AssistantRun

表示一次实际运行，包含：

- id、taskId、工作区身份；
- `workspaceId`、`workspaceGeneration`、`requestId` 和触发时的输入/候选 hash；
- 手动、定时或巡检触发来源；
- 开始和结束时间；
- 状态机：`queued`、`running`、`cancelling`、`cancelled`、`succeeded`、`failed`、`partial`、`awaiting_user`、`stale`；
- 心跳、租约、耗时、错误分类、取消原因和重试次数；
- Agent、Provider/Model、工具注册表和安全策略的完整快照及 hash；
- 关联的发现、投影消息、工具回执和实际来源快照。

### 5.3 AssistantFinding

表示助手发现的问题，包含：

- 问题类型；
- `workspaceId`、来源 `runId` 和规范化目标标识；
- 涉及的笔记路径、内容 hash、mtime 和必要的行范围；
- 判断依据、证据片段及证据 hash；
- 建议操作和可信程度；
- 新建、讨论中、已确认、已忽略、已完成、已失效等状态及状态变更原因；
- `fingerprintVersion`、稳定指纹、`duplicateOf`/`supersedes`，用于去重和笔记移动后的追踪；
- `projectionId`、`notifiedAt` 和待处理/已处理状态，用于主动消息幂等。

### 5.4 AssistantMemory

记忆只保存可复用的长期事实，不把所有运行记录复制成第二个事实源。至少包括：

- 用户偏好；
- 已确认的写作和整理规则；
- 用户确认的处理决定和长期约束；
- 记忆的工作区或全局作用域；
- 来源（用户、任务、发现或运行）、`userConfirmed`、可信程度、生效/过期时间；
- `supersedes`、脱敏状态和可删除标记。

任务、运行、发现和主对话分别是唯一事实源；原始记录负责完整保存，Context 只按当前任务选择相关记忆，并沿用已有压缩机制生成模型可用的派生上下文。

### 5.5 主助手投影与持久化

- 每个工作区只有一个持久的 `mainAssistantId` 和 `mainSessionId`；普通 Session 不能替代它，也不能承载后台运行。
- `AssistantProjection` 保存 `projectionId`、`runId`、`findingIds`、内容摘要、创建时间和已读/处理状态；同一投影重试或重启时必须幂等。
- 助手私有数据放在工作区 `.plexus/agent/assistant/`，使用 schema version、临时文件写入后原子 rename，并隔离损坏文件，不能影响普通聊天。
- 任务、运行、发现、投影、记忆和主助手索引分别持久化；摘要是派生数据，不能覆盖原始运行事实。
- 所有记录保存工作区身份；文件路径只作为当前工作区内的定位信息，内容变化时以 hash 和代际校验为准。

## 6. 运行模型

### 6.1 任务触发

第一阶段支持：

- 用户在助手面板中手动运行；
- 按时间定时运行；
- 后续可接入笔记变化事件触发。

调度器只在应用运行期间工作。应用关闭期间不执行；重新打开后不补跑关闭期间错过的周期，只等待下一个未来触发时间。

调度器是每个应用实例的单一 owner，使用持久化 `revision`、幂等键
`(workspaceId, taskId, scheduledAt, revision)`、租约和心跳去重。手动任务优先于定时任务；同一主助手同一时间最多一个主动运行。

工作区切换前进入 quiesce：停止接收旧工作区的新任务，取消并等待 queued/running/awaiting-user 运行；旧请求、确认、工具回执和投影都因旧 `workspaceGeneration` 失效。

### 6.2 运行时契约

不能直接把当前 `runAgent` 作为后台入口。先抽出无 UI、无 Session 的通用运行内核：

- `RunInput`：`runId`、输入 transcript、冻结的 Agent/Model/Tool policy、`workspaceId`、工作区根路径、`workspaceGeneration` 和取消信号；
- `RunSink`：追加 transcript/工具回执、持久化状态、记录 heartbeat、保存 snapshot 和错误；所有状态按 `runId` 键控；
- `ChatAdapter`：把通用运行结果接入现有 Session、Tab、聊天状态和前台确认；
- `AssistantRunAdapter`：把结果写入 AssistantRun，不创建影子 Session，不自动标题，不写普通聊天历史；
- `ToolContext`：携带 workspace token；所有 notes、Git、assets 和 AI 工具在执行前校验 workspace identity/generation；
- 后台策略：固定只读工具 allowlist，同时过滤给模型的 Schema；`allowWrite=false`、未知工具拒绝、后台 confirm 直接 fail-closed；
- 取消必须贯穿前端、Rust AI 请求和工具调用，不能只让 Promise 提前返回而留下仍在途的副作用请求。

现有 `runAgent` 保留为聊天适配器，通用内核完成后，普通聊天与 AssistantRun 才共享同一套模型流、Context、工具结果和压缩逻辑。

### 6.3 任务执行

```text
触发任务
    ↓
校验 workspaceId / workspaceGeneration，取得任务和调度租约
    ↓
冻结 Agent / Model / Tool policy / registry 快照
    ↓
本地候选筛选或准备搜索范围，记录候选 hash
    ↓
使用 AssistantRunAdapter 和显式只读 ToolDispatcher 执行通用运行内核
    ↓
保存 AssistantRun、AssistantFinding 和工具回执
    ↓
按 finding 状态幂等投影重要结果为主助手消息
    ↓
等待用户对发现进行对话处理，不在后台等待确认
```

后台运行入口使用显式只读 dispatcher，不允许直接执行笔记写入工具，也不向模型暴露写工具 Schema。用户确认后的修改由前台助手对话生成 `MutationPlan`，先校验路径、workspaceGeneration、内容 hash 和 operation token，再展示准确 diff；最终允许后才执行。前置条件失效时标记 finding stale 并重新确认。

修改协议固定为“发现对话 → 用户确认处理意图 → 生成 MutationPlan → 展示实际 diff 并最终允许/拒绝 → 执行”。多笔记拆分、合并或批量操作只有在具备 all-or-nothing 事务/回滚能力后才允许自动执行；否则保持 `awaiting_user`，不做部分落盘。

### 6.4 面板结构

AI 助手面板建议包含：

- 主助手对话区；
- 待处理发现；
- 定时任务；
- 当前和历史运行记录；
- 记忆摘要或最近记忆；
- 历史普通 AI 会话入口。

## 7. 实施计划

### P1：数据、运行时契约与助手面板骨架

- 新增带 schema version 的 Assistant 状态、主助手索引、任务/运行/发现/投影/记忆持久化结构；
- 建立每个工作区固定的 `mainAssistantId` / `mainSessionId`，并完成旧普通会话的兼容迁移；
- 抽取无 UI、无 Session 的通用运行内核，定义 `RunInput`、`RunSink`、workspace token 和 config snapshot；
- 为聊天和后台分别实现 `ChatAdapter`、`AssistantRunAdapter`，禁止通过影子 Session 复用后台运行；
- 将现有 AI 页面改造成助手面板；
- 保留普通历史会话；
- 增加任务、发现、运行记录、投影和记忆的空态及展示结构；
- 为主助手投影增加来源、处理状态和幂等 ID。

交付标准：助手面板可打开，主对话和普通历史会话不退化，主助手身份可稳定恢复，运行内核不依赖 Session/Tab/全局确认。

### P2：Assistant Runtime 与任务调度

- 将现有模型流、Context、Tools 和结果协议接入 `AssistantRunAdapter`；
- 新增固定的只读工具 allowlist、能力声明、Schema 过滤和未知工具默认拒绝测试；
- 新增任务创建、启停、运行和失败状态；
- 增加应用运行期间的定时调度；
- 增加单 owner 任务队列、优先级、租约、心跳、幂等键和重复触发保护；
- 增加贯穿前端、Rust 请求和工具调用的取消机制；
- 工作区切换时 quiesce、取消并等待旧任务，使用 workspace generation 拒绝旧回执；
- 后台 confirm 必须 fail-closed，不能弹窗或挂起等待用户。

交付标准：手动任务和定时任务都能执行，运行记录完整，重复触发只生成一个运行，后台任务不会等待写入确认，切换工作区不会串库。

### P3：笔记主动巡检

- 建立包含 path、mtime、content hash、标题、层级和链接的本地轻量索引；
- 监听文件变化并去抖、增量更新索引；
- 先用确定性规则和候选分桶筛选，再交给 AI 判断，限制全库扫描成本；
- 识别重复、相关、应拆分、疑似过时和冲突内容；
- 生成绑定 run、证据 hash、目标内容 hash 和生命周期的 AssistantFinding；
- 通过主助手对话主动告知；
- 对重复发现做版本化稳定去重，内容或路径变化时将旧发现标记为失效；
- 只有单笔记或具备事务/回滚能力的 MutationPlan 才进入写入确认流程。

交付标准：测试笔记库中的明确正例能被发现，无关反例不会被标记为高可信问题。

### P4：定时研究

- 支持指定主题和执行周期；
- 调用 Web 搜索并保存来源；
- 保存规范化 URL、检索时间、来源快照和内容 hash；
- 对比上次运行结果和已有笔记；
- 只报告新增或变化信息；
- 在助手面板中主动发起对话。

交付标准：同一结果不会重复打扰，新增结果有来源且能关联已有笔记。

### P5：长期记忆

- 只保存用户确认或明确来源的长期偏好、规则、决定和约束；
- 任务、运行、发现和对话保留在各自事实源，不复制成无界记忆；
- 为记忆建立作用域、来源、可信度、过期和相关性选择；
- 复用现有上下文预算与压缩机制生成派生上下文，不复用内存型 Session snapshot 作为持久记忆；
- 在助手面板中展示最近记忆和来源；
- 重启后恢复记忆并用于后续任务。

交付标准：助手能够在后续任务中使用此前确认的信息，且上下文不会因全部记忆注入而失控。

### 实施门槛

- P1 完成通用运行时契约、workspace token、主助手身份和持久化迁移前，不开始后台调度。
- P2 完成只读工具矩阵、请求取消、确认 fail-closed 和跨工作区竞态测试前，不开启自动巡检或定时研究。
- P3/P4 先验证候选索引和来源增量，再扩大模型上下文；不能以全库全文注入替代索引。
- P5 最后实施；长期记忆必须可追溯、可删除、可过期，不能自动把模型推断升级为用户偏好。

## 8. 风险与回退

| 风险 | 预防和应对 |
| --- | --- |
| 全库扫描成本过高 | 先做本地候选筛选，再交给 AI 判断；记录运行耗时和候选数量 |
| 自动任务与人工对话冲突 | 使用统一任务队列，同一主助手只允许一个主动运行；用户任务优先级更高 |
| 后台任务卡在确认弹窗 | 后台只读，运行结束为 `awaiting_user`；由前台助手面板接续对话和确认，后台运行本身不挂起 |
| 重复发现反复打扰 | 用工作区、问题类型、路径和证据生成稳定指纹 |
| 记忆无限增长 | 原始记录归档保存，模型上下文仅加载相关记忆并压缩旧叙事 |
| 工作区切换导致任务跑错 | 任务绑定工作区身份，切换时取消旧运行并重载新工作区任务 |
| 运行记录污染主对话 | 通用运行内核不依赖 Session；聊天和 AssistantRun 使用不同 Adapter，投影带 provenance 和幂等 ID |
| 只读策略被新工具绕过 | 工具使用 capability/side-effect 声明；后台固定 allowlist、过滤 Schema，未知工具 fail-closed，并为注册表做矩阵测试 |
| 调度重复或崩溃丢状态 | 使用 schema version、revision、幂等键、lease、heartbeat 和启动恢复状态机 |
| 确认期间文件发生变化 | MutationPlan 保存路径、workspaceGeneration、内容 hash 和 operation token；执行前 CAS，失效则重新确认 |
| 前端取消但后端仍运行 | 增加 request registry 和 `cancel_ai(requestId)`，取消贯穿 Rust 流、工具调用和 AssistantRun 状态 |
| AI 调用失败 | 持久化失败状态和原因，允许用户手动重试，不自动执行有副作用的重试 |
| 新面板影响旧会话 | 历史会话数据格式保持兼容，面板迁移失败时仍能打开普通会话 |

### 回退条件

- 助手后台任务出现未经确认的笔记修改；
- 任务状态与实际运行结果不一致；
- 主助手对话或历史会话无法恢复；
- 定时任务造成重复执行或持续打扰；
- 记忆加载导致主对话上下文不可用。

回退时优先关闭调度器和主动巡检，保留普通 AI 对话和现有工具调用能力；任务、运行和记忆数据不删除，等待修复后重新加载。

### 9.1 阻塞问题及处理

| 审核问题 | 本版处理方式 |
| --- | --- |
| `runAgent` 强绑定 Session，会污染主对话 | 新增通用运行时契约；使用 `ChatAdapter` 与 `AssistantRunAdapter`，后台不创建影子 Session |
| 工作区是全局状态，存在切库竞态 | 引入持久 `workspaceId`、`workspaceGeneration`、quiesce、cancel-and-await 和工具层代际校验 |
| `allowWrite=false` 不能证明后台安全 | 后台固定只读 allowlist，过滤模型 Schema，工具增加 capability/side-effect 策略，未知工具默认拒绝 |
| 调度与持久化缺少幂等和恢复语义 | 增加 schema version、revision、lease、heartbeat、状态机、幂等键和启动恢复规则 |
| 全局单 Promise 确认桥会覆盖请求 | 后台 confirm fail-closed；前台 MutationPlan 使用 run/finding/generation/hash/token 绑定，改为可排队的确认协议 |

### 9.2 重要问题及处理

- 主助手改为每个工作区唯一的 `mainAssistantId`/`mainSessionId`，普通 Session 只作为历史入口。
- 主动消息增加 `AssistantProjection`，带 `runId`、`findingId`、`projectionId` 和处理状态，避免污染上下文和重复插入。
- Finding 增加证据、内容 hash、指纹版本、失效状态和路径移动追踪。
- Memory 收窄为可复用的长期事实；任务、运行、发现和对话保持各自唯一事实源。
- 增加候选索引、增量去抖、来源快照、取消和崩溃恢复设计。
- 多笔记拆分、合并和批量写入在具备事务/回滚前不允许部分落盘。

### 9.3 保留的待确认假设

- `workspaceId` 的持久化载体和工作区目录移动后的迁移规则；本版先规定身份与代际，不假设 canonical path 永久不变。
- 主助手绑定的 Agent 是否允许在面板中切换；本版默认创建后固定 `agentId`，配置修改只影响下一次运行。
- Web 检索的来源范围、费用和限流策略；P4 实施前需补齐。
- 长期记忆是否允许跨工作区共享；本版默认工作区隔离，只有明确标记为 global 的事实才可共享。
