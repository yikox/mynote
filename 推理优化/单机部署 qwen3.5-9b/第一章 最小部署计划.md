## 方案与选择理由

```text
Pi Code Agent（Mac，本地 SSH 隧道）
  → OpenAI-compatible API
  → vLLM 0.18.1（WSL2）
  → RedHatAI/Qwen3.5-9B-quantized.w4a16
  → RTX 4070 Ti SUPER 16 GB
```

- 原始 9B 权重约 19 GB，无法在 16 GB 显存中同时为 KV Cache 留出可靠空间；因此使用 W4A16 checkpoint。
- 使用 `--language-model-only`：下载目录保留了 MTP 权重，但首阶段仅加载语言模型，降低首轮服务复杂度与显存压力。
- 上下文固定为 8192，`--gpu-memory-utilization 0.85`，优先跑通单请求服务而不是追求长上下文或并发。
- vLLM 提供现成的 OpenAI-compatible API 和自动工具选择，适合作为后续 Agent 接入基线。
- 官方 PyPI 在该机器上速度过低，Python 依赖改用清华 PyPI 镜像；HF API 从该机不可达，模型改从 ModelScope 下载。镜像中的 vLLM 0.18.1 wheel 已与官方 SHA-256 对比一致。

## 从零复现

以下命令在远端以 `yiko` 执行。前提是 Python 3.12 与 `uv` 可用；不使用系统 `pip`。

### 1. 创建目录和隔离环境

```bash
export BASE=/home/yiko/workspace/qwen35-agent-serve
export PY="$BASE/.venv/bin/python"
mkdir -p "$BASE"/{config,logs,models,scripts}
~/.local/bin/uv venv "$BASE/.venv" --python 3.12
```

### 2. 安装并锁定依赖

本次依赖下载使用清华镜像。首次安装后应立即冻结完整依赖；当前机器的可复现锁定文件是 `$BASE/config/requirements.lock.txt`。

```bash
~/.local/bin/uv pip install \
  --python "$PY" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  --index-strategy unsafe-best-match \
  'vllm==0.18.1' 'openai==2.24.0' 'modelscope==1.38.1'

~/.local/bin/uv pip freeze --python "$PY" \
  > "$BASE/config/requirements.lock.txt"
```

若在另一台机器完全复刻当前依赖集，复制此锁定文件后执行：

```bash
~/.local/bin/uv pip sync \
  --python "$PY" \
  --index-url https://pypi.tuna.tsinghua.edu.cn/simple \
  "$BASE/config/requirements.lock.txt"
```

### 3. 从 ModelScope 下载模型并校验

HF API 在本机不可达，使用 ModelScope。`master` 可能变化，下载后必须校验下面两份权重的哈希。

```bash
"$PY" - <<'PY'
from modelscope.hub.snapshot_download import snapshot_download

snapshot_download(
    'RedHatAI/Qwen3.5-9B-quantized.w4a16',
    local_dir='/home/yiko/workspace/qwen35-agent-serve/models/Qwen3.5-9B-quantized.w4a16',
    revision='master',
)
PY

cd "$BASE/models/Qwen3.5-9B-quantized.w4a16"
sha256sum model.safetensors model_mtp.safetensors
```

### 4. 写入服务参数与 API Key

```bash
cat > "$BASE/config/serve.env" <<'EOF'
MODEL_DIR=/home/yiko/workspace/qwen35-agent-serve/models/Qwen3.5-9B-quantized.w4a16
MODEL_ALIAS=qwen3.5-9b
HOST=0.0.0.0
PORT=8000
MAX_MODEL_LEN=8192
GPU_MEMORY_UTILIZATION=0.85
SERVED_MODEL_NAME=qwen3.5-9b
EOF

umask 077
openssl rand -hex 24 > "$BASE/config/api_key"
chmod 600 "$BASE/config/api_key"
```

### 5. 启动、停止与重启

当前机器已保留以下运维脚本，直接执行即可：

```bash
BASE=/home/yiko/workspace/qwen35-agent-serve
"$BASE/scripts/start.sh"
"$BASE/scripts/stop.sh"
"$BASE/scripts/restart.sh"
tail -f "$BASE/logs/vllm.log"
```

`start.sh` 的核心启动命令如下。脚本还会设置 WSL CUDA 库路径、Python 头文件路径、日志和 PID 文件；复现时优先使用脚本，不要手工遗漏这些环境变量。

```bash
"$BASE/.venv/bin/vllm" serve "$MODEL_DIR" \
  --host 0.0.0.0 \
  --port 8000 \
  --served-model-name qwen3.5-9b \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.85 \
  --language-model-only \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3 \
  --trust-remote-code \
  --api-key "$VLLM_API_KEY"
```

## 调用与连接方式

服务 API 为 `GET /v1/models` 与 `POST /v1/chat/completions`。远端机器本机验证时：

```bash
BASE=/home/yiko/workspace/qwen35-agent-serve
export QWEN35_API_KEY="$(cat "$BASE/config/api_key")"

curl --compressed http://127.0.0.1:8000/v1/models \
  -H "Authorization: Bearer $QWEN35_API_KEY"
```

该服务在 WSL2 内监听 `0.0.0.0:8000`，但 Windows 防火墙当前阻止其他局域网主机直连 TCP 8000。因此 Mac/Pi 的可用连接方式是 SSH 本地隧道：

```bash
ssh -fN \
  -o BatchMode=yes \
  -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:8000:127.0.0.1:8000 \
  yiko@192.168.31.107
```

隧道建立后，客户端 Base URL 为 `http://127.0.0.1:8000/v1`，模型为 `qwen3.5-9b`。Pi 的实际配置在本机 `~/.pi/agent/models.json`，API Key 仅引用环境变量 `$QWEN35_API_KEY`，不写入配置文件。

默认会启用 Qwen 思考；对短回答或 Agent 常规动作，客户端应传：

```json
{"chat_template_kwargs":{"enable_thinking":false}}
```
